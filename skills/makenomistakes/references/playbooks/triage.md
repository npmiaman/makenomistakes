# triage

**Probe:** Is this something you didn't create — a bug report, a feature request, an external PR — that needs sorting before anyone builds it? Tickets that `to-tickets` produced are already agent-ready; they skip triage.

**Tier:** Q — triage changes no code. Posting to the tracker (labels, comments, closing) is what it does; a close or `wontfix` on someone else's request is confirmed with the user first.

**Moves** — first read the [triage procedure](../procedures/triage/PROCEDURE.md) and its [agent-brief format](../procedures/triage/AGENT-BRIEF.md) in full. The tracker is `docs/agents/issue-tracker.md`'s, else GitHub issues when there's a GitHub remote and `gh`, else the [local tracker](../procedures/repo-setup/issue-tracker-local.md): one file per issue under `.scratch/<feature-slug>/issues/NN-<slug>.md` with a `Status:` line.
1. **Show what needs attention**: unlabelled, `needs-triage`, and `needs-info` with reporter activity — oldest first, one line each.
2. **Gather context** for the picked item: body, comments, prior triage notes; then two checks — **redundancy** (already implemented? search by domain concept) and **prior rejection** (`.out-of-scope/*.md`).
3. **Verify the claim before grilling**: reproduce the bug from the reporter's steps, or check out the PR and run it. Confirmed (with code path), failed, or insufficient detail.
4. Recommend one **category** (`bug` / `enhancement`) and one **state** (`needs-triage`, `needs-info`, `ready-for-agent`, `ready-for-human`, `wontfix`) with reasoning.
5. Grill if it needs fleshing out (the `grilling` procedure + the `domain-modeling` procedure).
6. Apply the outcome: an [agent brief](../procedures/triage/AGENT-BRIEF.md) for `ready-for-agent`; triage notes (established / still needed) for `needs-info`; a rejected enhancement goes to [`.out-of-scope/`](../procedures/triage/OUT-OF-SCOPE.md).
7. Every comment or issue posted during triage starts with `> *This was generated by AI during triage.*`

**Traps:** grilling before verifying · "please provide more info" instead of specific questions · re-asking what prior notes resolved · writing an already-implemented request to `.out-of-scope/`.

**Proof:** each triaged item exists on the tracker with exactly one category and one state; every tracker post starts with the AI disclaimer; a `ready-for-agent` item carries an agent brief in the AGENT-BRIEF template — behavioural, durable (no file paths or line numbers), concrete acceptance criteria, explicit out-of-scope — and the verified reproduction.

**Report adds:** the bucket counts, and per item: category · state · one-line reason.
